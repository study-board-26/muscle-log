目的とゴール

既存の類似アプリは「記録はできるが、次に何をすればいいか教えてくれない」か「メニューは出るが、なぜその動きなのかが分からない」のどちらかに寄っている。本アプリは理解（フォーム解説）と意思決定（重量提案）を、記録という1つのデータ基盤の上で接続することを目的とする。

プロダクトゴール

  • 効かせ方が分かる — 種目ごとに、どの筋が主働で、どの意識で動かすかを、フォーム解説動画と文章で確認できる
  • 迷わず重量が決まる — 初回は体格ベースの目安から、2回目以降は自分の実測値から自動提案する
  • 漸進性過負荷が途切れない — 前回の記録が常に見え、停滞したらデロードを提案する
  • 偏りに気づける — 週の筋群別ボリュームを目安と比べ、不足している筋群を明示する

成功指標（プロダクトKPI）

指標定義目標
記録継続率週2回以上の記録が8週継続したユーザー比率60%
提案採用率次回重量の提案をそのまま実行した割合70%
e1RM 更新率8週間で主要種目のe1RMが向上したユーザー比率80%
記録所要時間1セットの記録完了までの操作時間5秒以内

前提条件

  • 利用形態：単一ユーザーの個人利用。アカウント登録は必須としない（ローカル保存が既定）。
  • 実行環境：iPhone の Safari で動作する PWA（OPEN-1 確定）。ホーム画面に追加した状態での利用を前提とする（理由は NFR-9）。
  • 配信：HTTPS でのホスティングを必須とする。Service Worker は HTTPS または localhost でしか登録できず、これがないとオフライン動作（NFR-1）が成立しない。
  • 利用環境：ジム内での片手操作を主用途とする。電波が不安定な前提でオフライン動作を必須とする。
  • 対象ユーザー：筋トレ歴0〜3年程度の初心者〜中級者。競技志向のパワーリフター向けの周期化は対象外。
  • 目的の限定：筋肥大（ハイパートロフィー）を主目的とする。減量・増量の栄養管理は扱わない。

免責の前提。本アプリの重量提案は統計的な目安であり、医療・トレーニング指導行為ではない。初回起動時と提案表示部に、体調・既往症に応じた自己判断が必要である旨を明示する（FR-F4）。

スコープ

対象に含む

  • 種目マスタとフォーム解説動画／効かせ方の提示
  • ワークアウトのセット記録（重量・レップ・RIR）
  • 体重の記録と、体の写真の記録・比較
  • e1RM と筋群別ボリュームの分析
  • 次回重量・デロード・補助種目の提案
  • ルーティン（分割法）の管理
  • オフライン動作とデータのエクスポート

対象に含まない

  • 栄養・食事・カロリー・PFCの記録および目標提示
  • 睡眠時間・睡眠スコアの記録
  • 主観疲労・コンディションの日次入力
  • プレート計算機（バーベルの重量内訳表示）
  • 体組成ログ（体脂肪率・部位別周囲径の測定記録）
  • SNS共有・他ユーザーとの比較・フォロー機能
  • ウェアラブル連携、心拍・有酸素運動の管理

体組成ログの代替として、体重（FR-B5）と体の写真（FR-B6）の2つのみを扱う。

スコープ除外による設計上の影響。睡眠・主観疲労を入力として持たないため、デロード判定は客観データのみで行う。具体的には「e1RMの停滞」と「同一重量におけるRIRの低下傾向」の2指標を用いる（ALG-4）。主観入力に頼る一般的な疲労管理より判定が遅れる代わりに、入力コストがゼロで済むトレードオフを取る。

用語定義

RIR
Reps In Reserve。そのセット終了時に「あと何回挙げられたか」の主観値。0 = 限界、3 = 余裕あり。強度の指標として全セットで記録する。
e1RM
推定1RM（Estimated One Rep Max）。実測せずに、重量・レップ・RIRから換算した最大挙上重量。種目ごとの筋力推移を1本の線で追うための指標。
セットボリューム
部位ごとの週間の実施セット数。本アプリでは主働筋を1.0、協働筋を0.5として按分して集計する。
主働筋 / 協働筋 / 安定筋
その種目で主に力を発揮する筋 / 補助的に働く筋 / 姿勢保持に働く筋。種目詳細に役割つきで表示し、ボリューム按分の係数（1.0 / 0.5 / 0）にも使う。
ダブルプログレッション
目標レップ帯（例 8〜12回）の上限に達したら重量を上げ、レップを下限に戻す漸進方式。本アプリの重量提案の基本ロジック。
デロード
疲労を抜くために意図的に負荷を落とす期間。本アプリでは「1週間、ボリュームを約50%に落とし、重量は維持する」形を既定とする。
器具プロファイル
ユーザーが使える器具の構成（自宅ダンベルのみ / ホームジム / フィットネスジム等）。種目候補のフィルタ条件になる。

コアループ

本アプリの機能はすべて、次の1本のループに接続している。どの機能追加も「このループを速く・切れにくくするか」で判断する。

機能要件

優先度は P0 必須（これが無いとプロダクトが成立しない）、P1 重要（差別化要素）、P2 拡張。

A種目マスタとフォーム解説

Group A — Exercise & Form
ID要件詳細優先度状態
FR-A1種目マスタ種目ごとに、名称・使用器具・主働筋／協働筋／安定筋・目標レップ帯・漸進幅・効かせるコツ・よくある失敗・根拠の強さ・姿勢の警告・解説動画を保持する。44種目を収録し、うち32種目は筋肥大のエビデンスで選定したもの（付属文書「種目選定書」）、12種目は実施回数の多さから追加したもの。両者は curated フラグで区別する。P0済
FR-A2フォーム解説動画種目ごとに、その種目のフォームを解説した動画へのリンクを保持し、種目詳細と記録画面の両方から1タップで開けるようにする。動画は消えることがあるため、検索リンクも併記する。P0済
FR-A3使う筋の表示種目ごとに主働筋・協働筋・安定筋を、役割つきで一覧表示する。3Dモデル上での色分けは廃止した（v1.2）。自作モデルは品質が実用に届かず、外部アセットは調達コストが見合わなかったため。P0済
FR-A4効かせるコツの提示種目ごとに「ここを縮める意識」「肩甲骨を寄せたまま固定」等の指示を文章で提示する。3D上のホットスポット注釈は廃止した（v1.2）。P1済
FR-A5よくある失敗の提示種目ごとに、よくある崩れ方とその結果を文章で提示する。3DによるNGフォーム比較アニメは廃止した（v1.2）。フォーム解説動画がこの役割を担う。P1済
FR-A6部位からの種目逆引き8部位のタブから、その部位を主働筋とする種目一覧に辿れる。P1済
FR-A7器具プロファイル・フィルタ設定した器具構成で実施可能な種目のみを表示する。ルーティン作成・補助種目レコメンドにも同じフィルタを適用する。P1未
FR-A8テクニック提示種目ごとに、停滞時に使える手法（テンポ調整、ストレッチ種目としての可動域重視、レストポーズ、パーシャル）を解説付きで提示する。P2未
FR-A9根拠の強さの表示種目ごとに根拠の強さ（介入研究／メタ分析／EMG／原則）を表示する。急性のEMG振幅は筋肥大の予測因子として妥当性が検証されていないため、EMGのみを根拠とする種目を介入研究と同列に見せない。出典リンクもあわせて表示する。P1済
FR-A10姿勢の警告表示姿勢を誤ると効果が大きく落ちる種目（シーテッド・レッグカール、スタンディング・カーフレイズ 等）に警告を表示し、種目名だけでは誤選択を防げないため、記録画面でも同じ警告を出す。介入研究で2〜15倍の差が出ている項目であるため。P1済

B記録

Group B — Logging
ID要件詳細優先度状態
FR-B1セッション管理ワークアウトの開始・中断・終了を管理する。中断中もタイマーと入力内容を保持し、アプリ再起動後に復元する。P0済
FR-B2セット記録種目ごとに、重量・レップ数・RIR・セット種別（ウォームアップ／メイン）を記録する。前セットの値を初期値として引き継ぎ、±ボタンで調整して2タップ以内に確定できること。記録単位は種目マスタの指定に従い、「重量×レップ」と「重量×秒数」を切り替える（等尺性種目への対応）。P0済
FR-B3前回記録の表示入力欄の直上に、同一種目の前回実施内容（全セットの重量×レップ×RIR）と、前回比のe1RM差分を常時表示する。P0済
FR-B4レストタイマーセット確定と同時に自動起動する。目標レップ帯に応じた推奨秒数を既定値とし（低レップほど長い）、画面消灯中も継続し、完了時に通知する。P0済
FR-B5体重記録日付付きで体重を記録する。1日1件、後から編集可能。増減の週平均を併記する。P1済
FR-B6体の写真記録日付付きで写真を保存する。撮影ポーズのラベル（正面／背面／横）を付与し、同一ポーズの任意2枚を左右または重ねて比較表示する。撮影ガイド（前回写真の半透明オーバーレイ）で構図を揃える。P1済
FR-B7セッションメモセッション単位・セット単位に自由記述メモを残す（例「右肩に張り」「グリップ幅を1つ広げた」）。P2未
FR-B8記録の修正と削除過去のセットをタップして重量・レップ・RIR を修正できる。×で1セット削除、セッションごとの削除も可能。セッション削除時はぶら下がるセットも同時に消す。種目やセッションの付け替えはできない。許すと e1RM の推移と週間ボリュームの整合を保てなくなるため、種目を間違えた場合は削除して記録し直す。P1済
FR-B9オフライン記録ネットワーク接続なしで全ての記録操作が完了すること。同期機構を導入する場合も、書き込みはローカル優先とする。P0済

C分析

Group C — Analysis
ID要件詳細優先度状態
FR-C1e1RM 推移種目別にe1RMを算出し、時系列グラフで表示する（ALG-1）。自己ベスト更新時はマーカーで強調する。種目マスタで等価と定義された種目の記録は1本の線として連結する（例：ラットプルダウン → 懸垂。懸垂時は「体重＋加重」を重量として扱う）。P0済

FR-C3筋群ヒートマップFR-C2 の結果を人体図に色で反映する。不足＝寒色、適正＝中間、過多＝暖色。3Dから2DのSVG人体図に変更した（v1.2）。集計は実装済みで、図を描いて筋群に紐づけるだけで実現できる。P2未
FR-C4ボリューム過不足の判定経験レベル別の推奨レンジと比較し、不足・適正・過多を判定して一覧表示する（ALG-3）。P1済
FR-C5体重推移と写真タイムライン体重の推移グラフ（生値＋7日移動平均）と、写真のタイムラインを同一画面に並べ、任意時点の比較を可能にする。P1済
FR-C6左右差・弱点の検出片側種目（ダンベル・片脚種目）の左右の記録差、および部位間のe1RM伸長率の差から、弱点部位を抽出して提示する。P2未

Dレコメンド

Group D — Recommendation
ID要件詳細優先度状態

NFR-6データ保全記録の書き込みはトランザクションで行い、アプリ強制終了時にも直前のセットまで保持する。済
NFR-7アクセシビリティボリュームの過不足は色だけでなく「不足 / 適正 / 過多」の文字も併記する。主要な文字は最小14px、コントラスト比4.5:1以上。一部

アルゴリズム仕様

ALG-1推定1RM（e1RM）

Epley式を、RIRを加味した形で用いる。RIRぶんの余力を「実施できたはずのレップ」とみなして換算する。

// 有効レップ数 effReps = reps + rir // Epley 式 e1RM = weight × (1 + effReps / 30) // 例：80kg × 8レップ・RIR 2 e1RM = 80 × (1 + 10 / 30) = 106.7 kg

有効レップが12を超える範囲では誤差が大きくなるため、effReps > 12 のセットはe1RMの算出対象から除外し、グラフには表示しない。

ALG-2筋群別ボリューム按分

// 1メインセットあたりの寄与 prime → 1.0 セット secondary → 0.5 セット stabilizer → 0.0 セット（集計対象外） // 例：ベンチプレス 4セット 大胸筋 4.0 / 三角筋前部 2.0 / 上腕三頭筋 2.0

ウォームアップセットは集計しない。週の区切りは月曜0時起点とする。

集計の単位は「部位」ではなく「筋群」（v1.2で変更）。 文献の 10〜20セット/週 はもともと筋群あたりの数字であり、部位で判定すると 含む筋群の数が多い部位ほど過多と誤判定される。実際に「肩」は3頭、「足」は 4筋群を含むため、推奨テンプレートまで過多と出ていた。 34筋を17筋群にまとめ、判定は筋群ごとに行う（muscleGroups.json）。

1セットが1つの筋群に与える寄与は最大1.0までとする。合計にすると、 ベンチプレスの上腕三頭筋（外側頭0.5 + 内側頭0.5）が協働なのに主働と同じ量になるため。

ALG-3次回重量の提案（ダブルプログレッション）

// 目標レップ帯 [lo, hi]、直近セッションのメインセット群を評価 条件A：全メインセットで reps >= hi かつ 平均 rir <= 1 → 重量を1段階上げ、レップ目標を lo に戻す 上げ幅：バーベル上半身 +2.5kg／下半身 +5kg ダンベル +2kg（片手あたり）／マシン 1プレート 条件B：条件Aを満たさず、reps >= lo を全セットで達成 → 重量据え置き、レップを +1 狙い 条件C：reps < lo のセットが1つ以上ある → consecutiveFailures += 1 2セッション連続で該当した場合、重量を 10% 下げて再開

ALG-4デロード判定

睡眠・主観疲労を入力に持たないため、判定は客観指標2つのAND条件とする。

// 主要種目（ルーティン内のコンパウンド種目）ごとに評価 条件1：直近3セッションで e1RM の自己ベスト更新がない 条件2：同一重量帯における平均RIRが、4週間前と比べて 1.0 以上低下 条件1 かつ 条件2 を満たす主要種目が 2種目以上 → デロード週を提案 // 採用時の調整（1週間） セット数 × 0.5（切り上げ）／ 重量は維持 ／ RIR 3 以上を目標

判定の限界を明示すること。主観入力がないぶん、体調不良や生活由来の疲労は検知できない。提案は「そろそろ落としませんか」という提示に留め、強制はしない。また最終デロードから3週間以内は再提案しない。

ALG-5初回開始重量の提案

実測データがない種目に対してのみ適用する。体重比のストレングス基準に経験レベル係数を掛け、目標レップ帯へ換算したうえで、安全側に10%割り引く。

推定1RM = 体重 × 種目係数 × 経験レベル係数 開始重量 = 推定1RM × repFactor(目標レップ) × 0.9 // repFactor は ALG-1 の逆算：1 / (1 + reps/30)
種目係数（体重比 / 男性・目安）
種目初心者中級者上級者
ベンチプレス0.500.751.25
スクワット0.751.251.75
デッドリフト1.001.502.00
オーバーヘッドプレス0.350.550.80

身長・体重からの推定は初回限定とする。体格から扱える重量を当てる精度には限界があり、2回目以降は必ず実測ベース（ALG-3）に切り替える。既に扱っている重量をユーザーが入力した場合は、そちらを常に優先する。

上表は公開されている一般的なストレングス基準を丸めた目安であり、Phase 1では女性向け係数・体重階級補正を持たない。実データが貯まった段階での見直しを前提とする（OPEN-3）。

ALG-6週間ボリュームの目安レンジ

// 主要筋群（13） 初心者　：筋群あたり 8 〜 14 セット / 週 中級者　：筋群あたり 10 〜 20 セット / 週 // 補助的な筋群（4）：脊柱起立筋・内転筋群・前腕・腹斜筋 初心者　：筋群あたり 3 〜 9 セット / 週 中級者　：筋群あたり 4 〜 12 セット / 週 判定：レンジ下限未満 → 不足 　　　レンジ内　　　 → 適正 　　　レンジ上限超過 → 過多

補助的な筋群は別レンジで判定する（v1.2で追加）。 脊柱起立筋・内転筋群・前腕・腹斜筋は多関節種目で常に働くため間接的な刺激が多く、 直接12〜20セットを積む対象ではない。同じレンジで判定すると、 まともな構成でもこれらが必ず不足と出てしまう。

経験レベル間でレンジを重ねること（v1.2で修正）。 初心者 8〜12 / 中級者 12〜20 と隣接させていたため、13セットの構成が 初心者では過多、中級者では不足となり、どちらに設定しても不適切と判定されていた。 下限12は根拠が弱く、一般に引かれるのは 10〜20セット/週。

技術構成案

対象プラットフォームは iPhone 向け PWA で確定（OPEN-1 クローズ）。オフライン動作と写真のローカル保持という2条件を満たす構成を示す。

領域推奨理由
配信形態PWA（iOS Safari／ホーム画面に追加）OPEN-1 確定。種目マスタや解説動画の差し替えがストア審査なしで行える。ネイティブ化は後から Capacitor 等で被せられる。
ホスティングGitHub PagesHTTPS が自動で付き（NFR-10）、無料。Git は開発環境に導入済み。Vercel / Netlify でも要件は満たす。
ビルドNode.js LTS + Vite型チェックのために必要。開発マシンにのみ必要で、利用時のiPhone側には何も要らない。
フォーム解説YouTube へのリンク3Dの自作を取りやめた代替（v1.2）。アセットの制作・調達が不要になり、OPEN-2 と RISK-1 が解消した。
UIReact + TypeScript + Vite周辺の情報が多く、型チェックと相性がよい。
データIndexedDB（Dexie）オフライン前提。将来的な件数増に対してもインデックス検索で足りる。
写真Origin Private File System もしくは IndexedDB Blob端末外に出さない要件（NFR-5）を満たす。
グラフ自前SVG または軽量ライブラリ描画対象は折れ線とバーのみ。重量級のチャートライブラリは不要。
